# «Астра» — границы продукта

Этот документ отвечает на три вопроса: **что уже есть**, **что входит в каждый
релиз** и **чего мы не делаем**. Если идеи нет в этом документе — её нет в
работе (см. «Правила изменения объёма» внизу).

Бизнес-логика тарифов — в [BUSINESS_MODEL.md](BUSINESS_MODEL.md).

Обозначения: ✅ готово · 🔨 в работе · 📅 запланировано · ✖ не делаем
Тарифов два — **бесплатный** и **Pro**. Рекламы в приложении нет.
Уровни в таблицах: **Г** — бесплатно, без входа · **А** — бесплатно, нужен вход через Google
(синхронизация между устройствами) · **Pro** — подписка «Астра+» (оформляется без входа; вход нужен, чтобы подписка работала на других устройствах)

## 2. MVP — что осталось до Google Play

Функции MVP из концепции **готовы**. По решению владельца в MVP добавлена
**подписка «Астра+» и воронка с экспресс-тестом** (строки A–D ниже). Это
осознанное расширение: MVP вырос примерно на неделю, а «Астра+» ушла из 1.1.
Дальше — только то, без чего нельзя опубликоваться или удержать пользователя:

| # | Задача | Зачем | Оценка |
|---|---|---|---|
| **A** | **Подписка «Астра+»**: продукты в Play Console (месяц, 6 мес., год, пробные 7 дней), RevenueCat, экран оформления, восстановление покупок, проверка доступа | деньги; воронка из экспресс-теста | 3–4 дня |
| **B** | **Экспресс-тест в онбординге**: 5 вопросов, закрытый результат, экран предложения, карточка на вкладке «Тесты» + тексты (6 результатов, пишу я) | вход в воронку | 2–3 дня |
| **C** | **Подробная совместимость за «Астра+»**: «замок» на трёх блоках, предложение в момент интереса | ценность подписки | 0,5–1 день |
| **D** | ⛔ **Платёжный профиль для выплат** (см. [BUSINESS_MODEL.md §6](BUSINESS_MODEL.md)): без него нельзя создать подписки в Play Console | **блокер A**; решение владельца и юриста/бухгалтера | зависит от вас |
| 1 | Страницы политики конфиденциальности и удаления аккаунта (Firebase Hosting) | требование Google Play | 1 день |
| 2 | Ежедневный пуш + автопродление контента дня (GitHub Actions по расписанию) | удержание; контент не должен закончиться | 1–2 дня |
| 3 | Release-ключ подписи, App Signing, release-SHA в Firebase | публикация | 0,5 дня |
| 4 | Страница в магазине: иконка, скриншоты, описание, Data Safety («реклама отсутствует»), возрастной рейтинг | публикация | 1–2 дня |
| 5 | Включить принудительный App Check, сменить ключ сервисного аккаунта | безопасность | 0,5 дня |
| 6 | **Закрытое тестирование: 12+ тестеров 14 дней подряд** | требование Google Play для новых личных аккаунтов | 2 недели (параллельно) |

**MVP готов, когда:** закрыты все пункты A–D и 1–6, падений меньше 0,5 % сессий,
подписка оформляется и восстанавливается на реальном устройстве, и (для
личного аккаунта) 12 тестеров прошли 14 дней закрытого теста.

**Порядок:** сначала D (юридическое, идёт параллельно с кодом), одновременно
B и C, затем A — когда готов платёжный профиль. Закрытый тест можно начать на
текущей сборке уже сейчас, не дожидаясь подписки.

## 4. Чего не делаем (и почему)

| Идея | Почему нет |
|---|---|
| Чаты и консультации с «астрологами» | модерация, ответственность, расходится с тоном |
| Таро-расклады с «предсказаниями будущего» | риск пугающего контента; карта дня — про настроение, не про судьбу |
| Лента и соцсеть внутри приложения | модерация, приватность; делимся через Stories |
| Отслеживание геолокации и активности друзей | принцип приватности из концепции |
| Нумерология, Human Design, китайский гороскоп | размывает продукт; вернуться после 2.0 по данным |
| Веб-версия | мобильный ритуал + виджет; не раньше 2.0 |
| Генерация общего контента (гороскопы, профили) ИИ «на лету» | стоимость и контроль тона; общий контент готовим заранее и вычитываем. Исключение — Pro-рефлексия по дневнику (после запуска, по согласию) |
| Реклама: баннеры, межстраничная, при запуске | решение владельца: приложение без рекламы. Возможно позже только добровольная награда за ролик |
| Принудительный пейвол без кнопки «Не сейчас»; предложение при каждом запуске | решение владельца: предложение только мягкое — один раз после экспресс-теста и в моменты интереса |

## 5. Правила изменения объёма

1. **MVP заморожен.** Новая идея → строка в разделе «Идеи» ниже, не в работу.
2. Добавить функцию в текущий релиз можно, только **убрав** из него
   сопоставимую по объёму — и обновив этот документ.
3. Каждая функция в работе должна ответить: какую метрику из
   [BUSINESS_MODEL.md §7](BUSINESS_MODEL.md) она двигает?
4. Решения фиксируются здесь и в Pull Request; устные договорённости не считаются.
5. Пересмотр документа — после каждого релиза, по метрикам.
